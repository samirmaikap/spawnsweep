# SpawnSweep search and website baseline

Captured November 17, 2026 against the published site before this branch’s changes. The prior domain migration and benchmark are in [the November 16 snapshot](baseline-2026-11-16.md). Its results describe that earlier index snapshot and release state.

| Area | Observation | Implementation response |
|---|---|---|
| Architecture | GitHub Pages classic build publishes `main:/docs` from the public [SpawnSweep repo](https://github.com/samirmaikap/spawnsweep). Project homepage, FAQ and comparison were on one static HTML page. Media is checked into `docs/images/`. The Swift app, Claude plugin and release scripts have separate entry points. | Keep Pages and the app architecture. Render technical guides with a shared Jekyll layout and plain HTML output. |
| Host and redirects | The Pages deployment API reported `built` and HTTPS enforcement. The authoritative homepage returned 200 and approximately 36 KB of HTML. The original GitHub Pages URL redirected once to the HTTPS project path. Explicit `index.html` may also resolve, so the homepage uses the directory URL as canonical. [Public site](https://samirmaikap.dev/spawnsweep/) | Use `https://samirmaikap.dev/spawnsweep/` for canonicals, structured IDs, sharable URLs and sitemap locations. |
| Crawler access | The authority for this project is [host-root robots.txt](https://samirmaikap.dev/robots.txt). It allows crawling. A project-path robots file does not govern the host. Googlebot, Bingbot, OAI-SearchBot, ChatGPT-User, PerplexityBot, Perplexity-User and a browser UA received identical 200 HTML with no `X-Robots-Tag`. These probes test UA handling. Actual search crawler verification requires engine-side diagnostics or verified bot logs. | Retain host policy and render all content and navigation in crawlable HTML. Maintain explicit snippet image permissions. |
| Sitemap | The [root sitemap](https://samirmaikap.dev/sitemap.xml) already lists the product homepage and is advertised in robots. The [project sitemap](https://samirmaikap.dev/spawnsweep/sitemap.xml) contained only that same URL. The portfolio homepage card still linked to GitHub. | Build the project sitemap from actual guide routes and link every guide from the homepage and README. Publish and submit the project sitemap in both webmaster consoles. |
| Metadata | The live title and description already mentioned the category and agents. One canonical and Open Graph data existed. X cards relied on OG fallback. SoftwareApplication and duplicated FAQPage JSON-LD were present. | Improve consistent snippets and add explicit social fields. Use one application entity and reference it from technical guides. Retain the FAQ in visible HTML. |
| README and GitHub | Repo About links the canonical homepage, mentions macOS, AI coding agents, and supported tools, and includes 20 topics. The README covered features, install, free versus Pro, comparison and FAQs. Some copy implied universal process detection or guaranteed recovery. | Improve the README first section and contextual links. Qualify claims based on the scanner and cleanup code. Draft an About and topic update in [the keyword strategy](KEYWORD_STRATEGY.md). |
| Mobile and accessibility | The baseline was responsive at 375 px and 1280 px. Header nav collapses on narrow screens. The original install command and comparison table scrollers could be inaccessible to keyboard users. | Preserve layout, keep the Guides jump link visible on mobile, and make the existing scroll regions focusable. |
| Media | Screenshots already use sized JPEGs of roughly 76–84 KB, with explicit dimensions and offscreen lazy loading. The homepage demo is a 2.1 MB MP4 with a small poster and `preload="none"`. The README contains a 6.4 MB animation hosted by GitHub. | Reuse the site’s compressed and sized assets. Defer guide image loads and video payload. Measure the finished Pages build. |
| Performance | One Lighthouse 13.6.0 mobile lab run on the live homepage scored 100 performance, 100 accessibility and 100 SEO. LCP was 1.09 s, TBT 27 ms, CLS 0 and total transfer about 273 KiB. A single direct request recorded roughly 0.40 s TTFB. Field LCP, INP and CLS were unavailable. | Preserve the low initial payload and verify responsive behavior, local lab scores and keyboard accessibility separately. |
| No-JavaScript | The live homepage included headings, explanatory text, FAQ answers, links and the download CTA in the response. JavaScript powered the installer copy button and a sample cleanup interaction. | Preserve those controls and render all guide pages without JavaScript. |
| Search visibility | GitHub repository search retrieved the official repo for one broad category query and one branded query. One sampled web retrieval surfaced the OpenMacApps listing on the category query. The official website and repo did not appear in the four sampled tool retrievals. The brief reports a Google AI Overview that recommended Sluice with a Product Hunt citation. | Use the [tracker](DISCOVERABILITY_TRACKER.csv) for exact queries, scope and results. ## Search Console and Bing handoff

1. After approval and Pages deployment, confirm HTTPS 200 for the [homepage](https://samirmaikap.dev/spawnsweep/) and all [sitemap URLs](https://samirmaikap.dev/spawnsweep/sitemap.xml). Confirm canonicals and crawler response headers on the live origin.
2. In [Google Search Console](https://search.google.com/search-console/), use the existing `samirmaikap.dev` domain property if available. Otherwise verify with the domain owner’s DNS TXT record or use the project’s exact HTTPS URL-prefix property and an offered verification method. Submit the full project sitemap URL. Inspect the homepage and several priority guides and record discovered, indexed and canonical status. Review search impressions for non-branded query clusters. [Google's Search Console guide](https://developers.google.com/search/docs/monitor-debug/search-console-start)
3. In [Bing Webmaster Tools](https://www.bing.com/webmasters/), import the verified Google property if appropriate, or add the site and verify by its available DNS, file or meta-tag method. Submit the same project sitemap and inspect the live URLs and index results. [Bing site verification](https://www2.bing.com/webmasters/help/add-and-verify-site-12184f8b) · [Bing sitemap instructions](https://www.bing.com/webmasters/help/sitemaps-3b5cf6ed)
4. The portfolio owner can update the existing project card to link to the official site as part of a separate change. The current product URL is already listed in the host sitemap.

## Weekly discoverability check

Use the prompts in [the keyword strategy](KEYWORD_STRATEGY.md) and the exact existing queries in [the tracker](DISCOVERABILITY_TRACKER.csv). Keep branded checks in their own rows. Use a fresh signed-out browser or a fresh search-enabled chat when available and record locale, region, engine and result limit. For an AI answer, copy the cited URL and mark mentions, recommendations and citations separately. For result lists, record the official website, GitHub and verified third-party listings separately, with position only for a known result list.

Run the same sample before rollout, after confirming indexed pages, and weekly for eight weeks. Label unavailable or challenged sessions clearly. An HTTP response, an OpenAI web-search tool result, and a native ChatGPT Search recommendation are different observations. Keep historical rows and append current rows with the deployed commit. Google groups AI feature traffic with web search traffic in Search Console. [Google AI features guidance](https://developers.google.com/search/docs/appearance/ai-features)
