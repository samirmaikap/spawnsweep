# Security reporting

Send suspected vulnerabilities involving SpawnSweep, its installer, or its cleanup actions to [Samir Maikap through his published contact address](mailto:maikap.samir@gmail.com?subject=SpawnSweep%20security%20report). If GitHub offers **Report a vulnerability** on [the repository's Security Advisories page](https://github.com/samirmaikap/spawnsweep/security/advisories), you can also use that private form. [GitHub's private reporting guide](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/report-privately)

Include the SpawnSweep version or commit, macOS version, whether you used the official download or built from source, and the behavior and impact you observed. Use a disposable project for reproduction and redact license keys, `.env` values, credentials, and private paths. Keep sensitive reports in a private channel while the maintainer investigates and coordinates disclosure.

Check [the latest release](https://github.com/samirmaikap/spawnsweep/releases/latest) when reproducing a report from an older version. Use [GitHub Issues](https://github.com/samirmaikap/spawnsweep/issues) for ordinary bugs.

See [the installation and cleanup audit](reports/discovery/PRODUCT_TRUST.md) for release-verification steps, privacy practices, and cleanup limitations.
